# Модель прозрачности: локальный Opacity + LayerOpacity — план

_Живой документ. Дизайн согласован, реализация отложена. Ссылки на код — `путь:строка`._

---

## 0. Проблема

В WPF/Avalonia `Opacity` элемента — **всегда групповой**: он применяется к элементу **и всему его поддереву** (композитится как слой). Нет «локальной» прозрачности только на сам элемент. Поэтому если надо притушить **один** узел, не трогая детей, приходится курочить/дублировать дерево. Это известный wart, и от него хотим уйти.

При этом групповая прозрачность поддерева тоже нужна (выцветить целую группу как одно, с корректным блендингом на пересечениях). Значит — это **два разных свойства**, а не одно.

---

## 1. Модель (согласовано)

Два независимых свойства:

1. **`Opacity` — локальная (self).** Применяется только к **собственному** рендеру элемента (его фон/рамка/текст — то, что элемент рисует сам). В **логических детей не уходит**. Дёшево: просто множитель на свои примитивы, без offscreen-слоя. Это дефолт и частый кейс (притушить именно этот контрол).

2. **`LayerOpacity` — групповая (поддерево).** Композитит элемент + весь подграф в offscreen-слой и блендит целиком. Дорого, но корректно — пересекающиеся дети **не** удваивают альфу, затухание равномерное. Включается явно, когда реально нужна «вся группа как одно».

Дефолтный `Opacity` = локальный — это сознательное **расхождение с WPF/Avalonia** (там `Opacity` = групповой). Оправдано: частый дешёвый кейс получает простое имя и поведение, а дорогой слой — opt-in. Бенчмарк движка = Slate/Noesis, не WPF, так что расхождение приемлемо.

Полная цепочка альфы остаётся: `Color.A × Brush.Opacity × Element.Opacity(local)`, плюс `LayerOpacity` поверх (на уровне слоя).

---

## 2. Текущее состояние движка

- `Opacity` сейчас **каскадит попримитивно**: `DrawingContext` делает `opacity *= parent.Opacity` вверх по цепочке (`Adamantium.UI/Rendering/DrawingContext.cs:138-140`). То есть фактически групповое поведение, но **без** настоящего слоя (примитивно) → имеет боль WPF (уходит вглубь) **и** двойной блендинг на пересечениях.
- Каскад добавлен **специально** ради шаблонных контролов: чтобы `Button.Opacity` дотягивался до `Border` внутри шаблона (chrome) (см. комментарий `DrawingContext.cs:135`).
- В рендере альфа складывается из `Color.A × Brush.Opacity × RenderData.Opacity` в теле заливки (`UIRenderComponent`), fringe (`GpuFillRenderComponent`) и обводках (`GpuStrokeRenderComponent`); `RenderData.Opacity` = текущий каскадный Element.Opacity.

## 3. Реализация

### Локальный `Opacity`
Ключевой нюанс: у шаблонного контрола «self» — это его **шаблон (chrome)**, а не сам контрол. Поэтому локальный Opacity — **не** «просто убрать `*= parent.Opacity`». Нужно:
- Каскад Opacity **доходит до template-chrome** (Border/части шаблона), но **обрывается на границе логического контента** (ContentPresenter / логические дети).
- Т.е. пометить точку обрыва каскада = граница «свой шаблон vs логические дети». Логические дети начинают свой каскад заново со своего собственного Opacity.

### `LayerOpacity`
- Рендер поддерева в offscreen render target → композит в основную цель с `LayerOpacity`.
- Это **та же инфраструктура**, что и отложенный fix прозрачности в аналитическом AA (слой, чтобы пересечения не двоили альфу) — см. `ANALYTIC_AA_PLAN.md`. Одно потянет другое.

## 4. Открытые вопросы / нюансы

- **Существующие usages.** Сейчас есть элементы, рассчитывающие на каскад (напр. в Sandbox `RenderTargetPanel Opacity="0.95"`, `Button Opacity="0.8"`). При переходе на локальный Opacity их «затухание поддерева» исчезнет — где реально нужна группа, перевести на `LayerOpacity`.
- **Именование.** `Opacity` (local) + `LayerOpacity` (group). Альтернатива — `Opacity`(group, WPF-совместимо) + `LocalOpacity`. Выбрали первый вариант (дефолт = дешёвый локальный).
- **OpacityMask** (WPF) — пока вне скоупа.

## 6. ОБНОВЛЕНИЕ 2026-07-16 — что реально сделано (модель пересмотрена)

Реализация **разошлась** с моделью из §1. Решили **НЕ** флипать дефолт `Opacity` на локальный (чтобы не менять контракт/имя — это общее для всех поведение), а добавить локальную прозрачность **рядом**:

- **`Opacity`** — оставлен как есть: групповая WPF-семантика (композитится вниз по поддереву, попримитивно). Контракт не тронут.
- **`SelfOpacity`** (новое, `UIComponent`/`IUIComponent`) — притушивает **только собственную отрисовку** элемента, в поддерево НЕ уходит. Имя предварительно оставлено `SelfOpacity` (обсуждали `OwnOpacity`/`SurfaceOpacity`/`ElementOpacity`).

**«Запекание» обеих в снапшот (PUSHED `95fb2c5`):** обе вынесены из запечённого цвета в `LayoutSnapshot` (per-node `Opacity` + `SelfOpacity`); бейк компонует эффективную альфу из снапшот-цепочки (`RenderCache.EffectiveOpacity = SelfOpacity × Π(Opacity вверх по RenderParent)`, мемоизировано как `World`). Обе → `AffectsPaint`: смена = **O(dirty) перекрас слотов**, а не ре-рекорд. Перфоманс: полевые зеркала `_opacity`/`_selfOpacity` (без GetValue в горячем пути). См. память `opacity-in-snapshot-and-selfopacity`.

### Отложено (техдолг) — см. `TECH_DEBT.md`
1. **Вариант B — GPU per-node opacity-таблица.** Сейчас анимированная/меняющаяся element-`Opacity` = перекрас слотов (O(поддерева) на кадр). B = per-node альфа в GPU-буфере (BDA, зеркало `TransformTable`), **шейдер множит альфу live** → O(1), никакого перекраса. Требует правки 4 шейдеров (`BatchEffect.fx` rect/ellipse/gradient/fill, `FontEffect.fx`, `StrokeEffect.fx`, `FillFringeEffect.fx`) + регенерации бинарей (флейк-прон). Окупается на фейде **больших** поддеревьев; для мелких (оверлей/диалог) выигрыш копеечный — сегодняшний перекрас там уже хорош.
2. **Композитор-канал для element-opacity** (анимация на рендер-потоке, off-loop). `Compositor.TryTakeOver` для Paint ждёт Brush-таргет, поэтому анимированная element-opacity пока тикает на loop (но уже через дешёвый перекрас). Полноценный off-loop — это по сути B (рендер-поток пишет слот таблицы) + канал.
3. **`LayerOpacity` / offscreen-слой** (§1 п.2, §3) — не сделан. Групповая `Opacity` двоит альфу на пересечениях ДЕТЕЙ внутри поддерева: каждый ребёнок рисуется своей уже помноженной альфой, поэтому на нахлёсте фона остаётся `(1−α)²` вместо `(1−α)` — группа выглядит плотнее там, где дети налезают друг на друга. Там, где не налезают, каскад и слой дают пиксель в пиксель одно и то же, а с элементами СНАРУЖИ поддерева разницы нет вовсе. Каскадом это не лечится: два независимых рисования в одно место не сливаются, нужен именно слой — собрать поддерево при полной непрозрачности и положить один раз.

   **Связка с аналитическим сглаживанием СНЯТА (2026-08-24).** Прежняя редакция этого пункта утверждала, что offscreen-инфраструктура нужна заодно и для прозрачности аналитического AA. Это больше не так: самоперекрытия полупрозрачной ОБВОДКИ закрыты в `9937bbc` — покрытие объединения берётся как максимум через глубину (два прохода, ничьи разводятся серийным номером куска ленты), offscreen-цель не участвует; стенд «Translucent overlap» на вкладке Shapes это показывает, тесты `StrokeUnionRenderTests`. Осталось по AA только `§1c` — полупрозрачные ЗАЛИВКИ (заливка под своей же обводкой, самопересекающиеся контуры): там нужен `inset` тела на ~0.5 px, потому что тело растеризуется жёстко. Это отдельная задача, и `LayerOpacity` её не ждёт.
4. Локальный-vs-шаблон нюанс из §3 (обрыв каскада на границе chrome/логический контент) — при текущей модели неактуален (Opacity остался групповым, SelfOpacity — чисто self), но если когда-нибудь флипнём дефолт — вернуть.
